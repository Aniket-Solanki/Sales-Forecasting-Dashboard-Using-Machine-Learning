Complete Technology Stack DefinitionEvery tool is selected to balance developer velocity, scalable performance, and seamless Python machine learning integration.Frontend (User Interface)Framework: Next.js (App Router enabled) for Server-Side Rendering (SSR) and routing.Language: TypeScript (strict mode) to catch UI bugs at compile time.Styling: Tailwind CSS combined with Shadcn/UI for accessible, professional-grade components.State Management: Zustand (lighter and less boilerplate than Redux) for global state like user sessions and active filters.Data Fetching: TanStack Query (React Query) for caching API responses and managing loading/error states.Data Visualization: Apache ECharts (via echarts-for-react). It handles large datasets (10,000+ data points) much better than SVG-based libraries.Backend (API & Business Logic)Framework: FastAPI (Python) for asynchronous endpoints and automatic Swagger/OpenAPI documentation.Server: Uvicorn (ASGI web server).Data Validation: Pydantic (built into FastAPI) to strictly define incoming JSON payloads.ORM: SQLAlchemy 2.0 for interacting with the database using Python objects.Migrations: Alembic to track and apply database schema changes.Machine Learning & Data PipelineData Manipulation: Pandas and Polars (Polars is used for heavy, memory-intensive transformations).Modeling Framework: XGBoost (Extreme Gradient Boosting) and Scikit-Learn.Model Tracking: MLflow to log experiments, track hyperparameters, and store the .pkl model artifacts.Background Processing: Celery with a Redis message broker. This ensures heavy model training doesn't block the API from responding to users.Infrastructure & DevOpsDatabase: PostgreSQL 16.Caching/Queue: Redis.Containerization: Docker & Docker Compose.CI/CD: GitHub Actions (runs Pytest and ESLint on every commit).2. The Machine Learning Pipeline SpecificationYou cannot just throw raw dates and sales into an ML model. The pipeline must follow these exact automated steps inside your Celery worker:Imputation: Fill missing days with 0 for units sold. Sales data is rarely continuous.Feature Engineering (The most important step):Lag Features: sales_t-1, sales_t-7, sales_t-30 (What were the sales yesterday, last week, last month?).Rolling Statistics: 7-day rolling mean, 30-day rolling standard deviation.Temporal Features: day_of_week, is_weekend, month, is_holiday.Train/Test Split: Time-series cross-validation. Never use random splitting; always train on the past to predict the future (e.g., train on 2021-2023, test on Q1 2024).Evaluation Metric: Use Mean Absolute Percentage Error (MAPE) to evaluate accuracy before saving the model:$$MAPE = \frac{1}{n} \sum_{i=1}^{n} \left\vert{} \frac{y_i - \hat{y}_i}{y_i} \right\vert{} \times 100$$4. Core API Contract (FastAPI)Your Next.js frontend will communicate with the backend exclusively through these RESTful endpoints.Auth:POST /api/v1/auth/login: Accepts JSON email/password, returns a JWT (JSON Web Token).Dashboard Data:GET /api/v1/dashboard/summary: Returns total revenue, predicted revenue, and month-over-month growth.GET /api/v1/dashboard/timeseries?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD: Returns an array combining actual sales and predictions for charting.Machine Learning Actions (Admin Only):POST /api/v1/ml/train: Triggers the Celery worker to retrain the model on the latest data.POST /api/v1/ml/predict: Triggers batch inference for the next 30 days.5. Sequential Execution PlanTo build this without getting tangled in dependency hell, you must build from the data layer outward. Do not start with the UI.1.Environment & Repository Setup:DevOps.Initialize the Git monorepo. Create the docker-compose.yml file to spin up PostgreSQL and Redis. You need these running locally before writing any application code.2.Database Models & Migrations:Backend.Initialize the FastAPI project. Write the SQLAlchemy models for Users, Products, Sales_History, and Forecasts. Run Alembic to generate and apply the SQL tables to your Postgres container.3.Authentication & Core APIs:Backend.Implement JWT authentication in FastAPI. Build the CRUD (Create, Read, Update, Delete) endpoints for uploading historical sales data and fetching it back out via date filters. Test everything using FastAPI's built-in Swagger UI at localhost:8000/docs.4.Jupyter Prototyping:Machine Learning.Temporarily leave the backend. Open a Jupyter Notebook. Connect to the local Postgres database, pull the data into a Pandas DataFrame, write your feature engineering logic, and train the XGBoost model. Validate that your model actually works before automating it.5.ML Pipeline Automation:Backend.Convert your Jupyter Notebook code into production Python scripts. Configure Celery to run these scripts as background tasks. Create the FastAPI endpoints (/api/v1/ml/train) that trigger these tasks.6.Frontend Scaffolding & Auth:Frontend.Initialize the Next.js project. Install Tailwind and Shadcn. Build the Login screen. Implement logic to store the JWT securely in an HTTP-only cookie and create route guards to protect the dashboard pages from unauthenticated users.7.Dashboard Implementation:Frontend.Build the main UI layout. Create the ECharts component that fetches data from GET /api/v1/dashboard/timeseries. Render the historical data as a solid blue line, the predictions as a dashed purple line, and the confidence intervals as a shaded area.8.Final Integration & Deployment:DevOps.Write Dockerfiles for the Next.js app, the FastAPI app, and the Celery worker. Deploy the database to AWS RDS, and push the Docker containers to AWS ECS or Google Cloud Run.
